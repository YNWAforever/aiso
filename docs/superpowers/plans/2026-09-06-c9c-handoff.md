## Concurrency and evidence review

The reviewed write path first replays an existing owned opportunity identity, then re-reads the source and conditionally inserts against the same account/client ownership and exact persisted source values. A unique account/client/opportunity key resolves duplicate saves; a losing request re-reads the owned winner. PATCH updates only title/action/notes and uses revision compare-and-swap, with identical normalized older-revision replay and conflict for differing stale or future revisions. Failed persistence never returns success.

Snapshots are server-derived, allowlisted, fixed to the original locale and initial copy, immutable on edit, and bounded to 65,536 UTF-8 bytes in application validation plus PostgreSQL JSONB-text enforcement. Pulse raw answers remain private; only a digest participates in change detection. Scan evidence retains validated version/provenance/redaction/limitation fields. Partial source and saved-mapping failures are explicit; all-source failure is a 503.

Mock/unit review covers source mutation or disappearance, forged fingerprints, duplicate replay results, revision races, tenant ownership, malformed/oversize bodies, JSONB size backstop, private-answer non-exposure, source exclusions, partial reads and bilingual plain-text rendering. Actual concurrent PostgreSQL execution remains unrun and is not claimed.
