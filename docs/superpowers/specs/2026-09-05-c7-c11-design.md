## C7 implementation design

Four review units: scan submission; versioned diagnostic gate and evidence presentation; methodology; claim/error compatibility.

- Add localized `/scan` using the existing ScanForm and submission API. Preserve request validation, rate limits, quotas, persistence semantics and redirects. Expose pending, partial, failure and retry states without sending additional provider requests.
- Extend the diagnostic methodology with weighted coverage gates: below 0.67 suppress the numeric pillar score; from 0.67 to below 0.85 label provisional; at least 0.85 label scored. Compare unrounded coverage at the boundaries. Explicitly not-applicable checks leave both numerator and denominator; missing, failed or unverifiable collection stays in the denominator and contributes no observed coverage. Zero applicable weight yields insufficient evidence, never a perfect score.
- Use C6's validated collection/applicability evidence through a pure scoring input seam, avoiding circular dependencies between the pillar module and the evidence normalizer. Do not infer not-applicable from absent results. Ambiguous partial assessment must not count as fully verified coverage.
- Bump the pillar methodology version for newly calculated snapshots. Read historical stored snapshots under their original version without rewriting them. Clearly label legacy snapshots and recalculated historical diagnostics; do not claim verified collection where old scans lack evidence. Preserve stored headline score, grade and scoring weights.
- Render sanitized evidence, collection limits, coverage and method version within the established result-access boundary. Preserve public teaser versus owned detail separation, signed claims and report revocation. Estimates remain labelled estimates; current origin-only evidence cannot substantiate improvement comparisons.
- Add localized `/methodology` explaining overlapping pillars, thresholds, method versions, missing provider/collection evidence, historical data and comparison limits. Activate only implemented NAV routes and derive exact sitemap coverage.
- Keep `/result/[id]` and its established layout/guards. Preserve signed claim-intent/claim and AuthComplete semantics. Test owner mismatch, invalid/expired claims and signup return rather than replacing the claim lifecycle.

Verification: threshold and just-below-boundary tests; zero/all-not-applicable coverage; unchanged legacy snapshots/headline scores; server DTO leakage and cross-account denial tests; submission/persistence/provider/429/quota/auth error cases; bilingual desktop/mobile browser checks including existing claim and pricing regressions. Independent review before the local handoff. Real Auth/database staging acceptance remains a separately recorded external gate.
