## Review and delivery guidance contract

Review help is a disclosure beside the existing SME step, shown only for the
selected, independently identified latest pending version when its server
`canDecide` is false. A newer saved draft does not erase that frozen version.
Opening or retrying the disclosure reads the existing session-owned
`GET /api/account/members`; closed, flag-off and other version states add no read.
The returned self must match the authenticated viewer, with an active self row,
unique canonical UUIDs and real active/approver booleans. Invalid or unavailable
reads remain unknown. The summary excludes both viewer and submitter, uses no
names or count metric, and describes account-role information only. It never
enables a decision or claims that another member can review this brand/version.

Client scope includes brand, item, version, content hash and viewer. Close, retry
and scope changes invalidate older completions; reopening performs a fresh read.
The member-settings anchor uses the existing `settings#members` section and honors
unsaved navigation guards. Existing decision fields, reasons and retry identities
remain mounted throughout help reads.

Handoff recovery uses only the accepted current read state. Confirmed entitlement
blocks can link to `settings#settings-plan`; disconnected or capped handoffs can
open the existing manual-delivery disclosure. Opening that pane preserves its
forms and independently gated export/record authority; it starts no export or
handoff. `not_approver` means the member who actually approved this version, so
member-role changes are not offered as a solution. Loading, busy, unknown,
unconfirmed or stale authority adds no recovery advice. Existing independently
authorized live-check behavior remains intact; an unknown outcome never becomes
resend authority.

## Controlled journey implementation

The acceptance work reuses actual components behind a closed sample transport.
Its Node factory derives a genuine scan suggestion and canonical draft snapshot,
then freezes the actual saved draft with the existing review freezer. Two browser
contexts operate on the same draft/version/hash and different sample actors;
this is controlled UI evidence, not real authentication or grants. Outcome reads
must visibly match the active delivery anchor/version/hash after recording and
reload, with all three immediate windows not due and no selected observation.

The standalone files embed actual CSS/runtime/messages and finite exact Node-frozen
sample revisions. Unsupported edits do not acquire a sample hash, and unsupported
routes/downloads/providers report their limits. Node crypto remains outside the
client graph. Reproduction, provenance and omitted layout context are in the
[preview guide](sme-activation-preview.md); participant tasks and blank observations
are in the [SME script](sme-activation-usability.md). Human acceptance is pending.

## Contracts and release gates

No new public API/write inputs, schema/migrations, task statuses, role grants,
entitlement, billing, provider or schedule policy. Flag-off/default API reads and
legacy presentation retain their previous behavior. Reuse independently scoped
handlers and current server capabilities for every actual operation.

Each candidate needs lint zero errors/warnings, Next type generation/TypeScript,
text audit, full unit/build, actual fixture generation, complete relevant browser
regression and all ten required exact-head CI jobs. Verify fresh head/base/CLEAN,
matched-head merge and tested/merged tree equality, canonical Ready full SHA and
production schema gate, then explicitly allowlisted read-only release evidence.
HTTP method alone is insufficient: export GETs write receipts, and dashboard
`?step=roi` may create a Local Trust snapshot. Audit exact paths, query parameters,
callee behavior and prefetch before expanding canonical reads.
